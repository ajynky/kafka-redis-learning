# Spring Kafka Outbox Demo

Order flow with **Spring Boot 4**, **Kafka**, **Redis**, **PostgreSQL**, and **OpenTelemetry**.
It covers the transactional outbox, idempotent consumers, ShedLock, and tracing one order end to end in Grafana.

Flow diagram: [kafka-redis-demo/kafka-redis-demo/README.md](kafka-redis-demo/kafka-redis-demo/README.md)
Learning notes + command cheat sheet: [NOTES.md](NOTES.md)

## How it works

1. `POST /orders` saves the order **and** an outbox row in one Postgres transaction (no Kafka call in the request).
2. `OutboxRelayService` (`@Scheduled`, ShedLock) sends unpublished outbox rows to topic `orders` with an `eventId` header and continues the request's trace.
3. Consumers (one group each):
   - `order-service` saves the order and status `CREATED` to Redis
   - `payment-service` pays once per `eventId` (idempotent, Redis), then publishes `PAID`/`FAILED` to `payments`
   - `notification-service` notifies and saves the final status to Redis
4. `GET /orders/{id}` and `GET /orders/{id}/status` read from Redis.
5. `OutboxCleanupService` deletes published outbox rows older than 7 days (daily, ShedLock).

## Run locally

### 1. Secrets
```
copy .env.example .env
```
Edit `.env` and set real values. `.env` is git-ignored. Docker Compose and Spring both read it.

### 2. Infrastructure
```
docker compose up -d
```
Grafana runs at http://localhost:3000 (login `admin` / `admin`).

### 3. Database schema (first time only)
Hibernate runs with `ddl-auto: validate`, so create the tables once:
```sql
CREATE TABLE orders (
    order_id   VARCHAR(255) PRIMARY KEY,
    order_data TEXT NOT NULL,
    created_at TIMESTAMP(6) WITH TIME ZONE NOT NULL
);

CREATE TABLE outbox (
    id           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    topic        VARCHAR(255) NOT NULL,
    message_key  VARCHAR(255) NOT NULL,
    payload      TEXT,
    created_at   TIMESTAMP(6) WITH TIME ZONE NOT NULL,
    published_at TIMESTAMP(6) WITH TIME ZONE,
    trace_parent VARCHAR(55)
);

CREATE TABLE shedlock (
    name       VARCHAR(64)  NOT NULL PRIMARY KEY,
    lock_until TIMESTAMP    NOT NULL,
    locked_at  TIMESTAMP    NOT NULL,
    locked_by  VARCHAR(255) NOT NULL
);
```
Run it with:
```
docker exec -it postgres psql -U <POSTGRES_USER> -d <POSTGRES_DB>
```
Flyway migrations are planned. They will replace this step.

### 4. Application
Open `kafka-redis-demo/kafka-redis-demo` in IntelliJ and run `KafkaRedisDemoApplication` with:
- Active profile: `local`
- VM options: `-Duser.timezone=UTC`

From the command line, in `kafka-redis-demo/kafka-redis-demo`:
```
mvn clean verify -DskipTests
java -Duser.timezone=UTC -Dspring.profiles.active=local -jar target/kafka-redis-demo-*.jar
```
Tests are skipped for now because the test profile has no database yet (Testcontainers is planned).

Second instance (multi-instance test): add `-Dserver.port=8081` as a VM option.

## Try it

```
curl -i -X POST "http://localhost:8080/orders?orderId=1&orderData=Book"
curl -i http://localhost:8080/orders/1
curl -i http://localhost:8080/orders/1/status
```
Expected status: `{"orderId":"1","status":"PAID"}`. An `orderData` containing `fail` gives `FAILED`.

Postman: import [kafka-redis-demo.postman_collection.json](kafka-redis-demo.postman_collection.json).

| Case | Response |
|---|---|
| Duplicate `orderId` | 409 |
| Unknown id on GET | 404 |
| Postgres or Redis down | 503 |
| Kafka down | POST still 200; the relay sends once Kafka is back |

## Observability (Grafana, http://localhost:3000)

- **Logs**: Explore -> Loki -> `{service_name="kafka-redis-demo"} |= "<orderId>"`
- **Traces**: Explore -> Tempo -> Trace ID (copy the ID from the `Order saved orderId=...` log line). One trace covers POST -> outbox relay -> Kafka -> all consumers.
- **Metrics**: Explore -> Prometheus -> `{service_name="kafka-redis-demo"}`
